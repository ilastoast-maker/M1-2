# 일어나 — 제품 요구사항

## 1. 제품 정의

**일어나**는 삼성 헬스의 일일 활동 스크린샷과 사용자가 입력한 체중 기록을 바탕으로, 부담 없이 운동 습관을 돌아보게 돕는 성인용 AI 운동 비서다.

태그라인: **내 기록을 이해하는 다정한 운동 비서**

의료·건강 진단 서비스가 아니며 질병, 약물, 치료, 극단적인 감량 방법을 안내하지 않는다.

## 2. 사용자와 핵심 원칙

- 만 19세 이상 성인만 사용한다.
- Google 로그인으로 사용자를 식별하며 Firebase UID로 데이터를 분리한다.
- 사용자를 체중이나 목표 달성 여부로 평가하거나 압박하지 않는다.
- 답변은 짧고 따뜻하게 작성하고, 실제 기록을 근거로 실천 제안은 한 번에 하나만 제공한다.
- 원본 건강 데이터 전체가 아니라 서비스에 필요한 최소 데이터만 저장한다.

## 3. 확정된 사용자 경험

### 온보딩

Google 로그인 후 다음 정보를 받는다.

- 나이
- 성별: 남성, 여성, 선택 안 함
- 키(cm)
- 현재 체중(kg)
- 목표 체중(kg)

일일 목표 걸음 수는 직접 입력받지 않는다. AI가 프로필과 최근 활동 기록을 바탕으로 100보 단위로 추천한다.

### 운동 기록

- 삼성 헬스 `일일 활동` 화면 스크린샷 한 장을 받는다.
- 사용자가 기록 날짜를 직접 지정한다.
- AI가 걸음 수, 활동 시간, 활동 칼로리, 이동 거리를 추출한다.
- 추출 결과는 저장 전에 사용자가 확인하고 수정한다.
- 같은 날짜의 활동 기록이 있으면 덮어쓰기 여부를 확인한다.
- 기존 삼성 헬스 ZIP은 최초 데이터 구축에만 사용할 수 있으며 원본을 저장소에 넣지 않는다.

### 체중 기록

- 사용자는 언제든 날짜와 체중을 기록할 수 있다.
- 마지막 체중 기록 후 7일이 지나 앱에 접속하면 인앱 알림을 표시한다.
- 알림은 `지금 기록하기`, `나중에`, `이번 주 건너뛰기`를 제공한다.
- 새 체중 기록은 프로필의 현재 체중도 갱신한다.

### 걸음 목표

- 최초 설정 후 AI가 목표 걸음 수를 추천한다.
- 매주 최근 기록을 바탕으로 새 목표를 제안한다.
- 사용자가 수락해야 목표가 변경된다.
- 추천값은 100보 단위이며 백엔드에서 허용 범위를 검증한다.

### 채팅

- 사용자당 하나의 연속 대화를 사용한다.
- 로그인하면 기존 대화를 자동으로 불러온다.
- 오래된 메시지는 요약하고 최근 메시지만 모델 컨텍스트에 포함한다.
- `대화 초기화`로 전체 대화를 삭제할 수 있다.

## 4. BMI 안전 가이드

BMI는 `체중(kg) / 키(m)^2`로 계산하되 진단이 아닌 참고 지표로만 표시한다.

- BMI 30 이상: 비난하지 않는 격려형 안내와 점진적인 활동 제안
- BMI 17 미만: 염려형 안내, 감량·활동 목표 상향 억제, 전문가 상담 권유
- 목표 체중의 BMI가 17 미만이면 저장 전에 재확인
- 정상 범위에서는 BMI를 반복적으로 강조하지 않음

## 5. 화면 구조

모바일 하단 메뉴 5개를 사용한다.

1. 홈: 오늘 목표, 주간 요약, 체중 기록 알림
2. 기록: 스크린샷 업로드, 체중 입력, 데이터 수정·삭제
3. AI 채팅: 운동 기록 기반 대화
4. 대화 기록: 날짜별 메시지 탐색과 초기화
5. 설정: 프로필, 목표 체중, 개인정보 표시, 로그아웃

## 6. 디자인 방향

- 따뜻한 코랄·오렌지와 차분한 네이비 조합
- 넉넉한 라운드 카드와 알약형 버튼
- 카드 중첩은 피하고 정보 위계를 단정하게 유지
- 좁은 모바일 화면을 우선 설계하고 데스크톱에서는 중앙 앱 셸로 표시
- 완전한 검정보다 짙은 네이비 기반 다크 모드
- 키보드 포커스, 충분한 대비, 44px 이상의 터치 영역, 모션 감소 설정 지원

## 7. 데이터 모델

Firestore 컬렉션:

- `profiles/{uid}`: 온보딩 정보와 현재 목표
- `data/{recordId}`: `(date, value, memo)` 기반 시계열 기록
- `conversations/{uid}`: 사용자별 단일 대화의 메타데이터와 누적 요약
- `conversations/{uid}/messages/{messageId}`: 시간순 메시지 문서

`data` 문서는 `record_type`으로 구분한다.

- `activity`: `value`는 걸음 수, 추가 지표는 활동 시간·칼로리·거리
- `weight`: `value`는 체중 kg

모든 데이터 문서에는 `user_id`를 저장하고 서버가 인증 토큰의 UID와 일치하는 문서만 접근한다.

날짜는 `YYYY-MM-DD`의 Asia/Seoul 달력 날짜로 해석하고, 생성·수정 시각은 UTC로 저장한다. 한 사용자는 날짜별로 활동 1건과 체중 1건만 가질 수 있으며 문서 ID를 결정적으로 생성해 중복을 서버에서도 차단한다.

## 8. API

필수 API:

- `POST /api/data`
- `GET /api/data`
- `PUT /api/data/{id}`
- `DELETE /api/data/{id}`
- `GET /api/data/summary`
- `POST /api/conversations`
- `GET /api/conversations`
- `GET /api/conversations/{id}`
- `DELETE /api/conversations/{id}`
- `POST /api/chat`

확장 API:

- `GET /api/profile`
- `PUT /api/profile`
- `POST /api/profile/weight`
- `POST /api/profile/step-goal/recommend`
- `POST /api/profile/step-goal/accept`
- `POST /api/data/import/screenshot`
- `GET /api/data/export.csv`
- `DELETE /api/account`

`GET /api/conversations`는 과제 호환성을 위해 `현재 대화` 한 항목을 목록으로 반환한다. `POST`는 전체 대화 교체가 아니라 전달된 메시지를 추가하며, 일반 채팅 저장은 `/api/chat`이 자동으로 수행한다.

## 9. 보너스 기능

- 주간·월간 걸음 수 그래프
- 체중 변화 그래프
- CSV 내보내기
- 라이트·다크 모드
- Function Calling과 MCP는 핵심 기능 완료 후 후순위

## 10. 개인정보 및 운영

- Firebase ID 토큰을 백엔드에서 검증한다.
- 이메일을 문서 키로 사용하거나 OpenAI에 전달하지 않는다.
- 업로드 이미지는 메모리에서 처리하고 영구 저장하지 않는다.
- OpenAI 요청에는 저장 비활성화 옵션을 사용한다.
- 서비스 계정 JSON과 API 키는 환경 변수로만 관리한다.
- 실제 삼성 헬스 ZIP, 스크린샷, 개인 데이터는 Git에서 제외한다.
- Render 콜드스타트와 네트워크 오류에 복구 안내를 제공한다.
- 최초 이미지 업로드 전에 OpenAI 처리 고지를 확인받는다.
- 계정 삭제 전에 CSV 내보내기를 안내하고, 명시적 확인 후 프로필·데이터·대화를 삭제한다.
- 공개 배포에서는 사용자별 AI 호출 횟수와 이미지 크기를 제한한다.

## 11. 완료 기준

- 로그인한 사용자만 자신의 기록과 대화에 접근할 수 있다.
- 스크린샷 한 장에서 4개 활동 지표를 추출하고 확인 후 저장할 수 있다.
- 활동 및 체중 CRUD와 요약이 동작한다.
- AI 답변이 사용자 데이터 요약을 반영한다.
- 단일 대화가 자동 저장·복원·삭제된다.
- 그래프, CSV, 다크 모드가 동작한다.
- `/docs`에서 API를 확인할 수 있다.
- README에 로컬 실행, 환경 변수, 배포 절차, 제출 자료가 정리된다.
