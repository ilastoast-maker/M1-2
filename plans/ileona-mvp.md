# 일어나 MVP 구축 계획

## 목표

Google 로그인, Firestore 사용자 격리, 삼성 헬스 스크린샷 추출, 운동 기록 CRUD·요약, 단일 AI 대화, 주간 목표 추천, 그래프·CSV·다크 모드를 갖춘 모바일 우선 웹 서비스를 구축한다.

## 불변 조건

- 프론트엔드는 HTML/CSS/JavaScript만 사용한다.
- 백엔드는 FastAPI와 Pydantic v2를 사용한다.
- 프로덕션 데이터는 Firestore에 저장한다.
- 인증된 UID가 모든 데이터 접근 범위를 결정한다.
- 업로드 이미지와 삼성 헬스 원본은 영구 저장하거나 Git에 포함하지 않는다.
- 커밋과 푸시는 사용자 승인 전 수행하지 않는다.

## 의존 관계

```text
1 → 2 → 3 → 4
1 → 5
(3, 4, 5) → 6 → 7
```

## Step 1 — 계약과 프로젝트 골격

### 컨텍스트

빈 저장소에 백엔드·프론트엔드·문서 디렉터리를 만들고 제품 요구사항과 환경 변수 계약을 고정한다.

### 작업

- 제품 요구사항과 API 계약 작성
- `.gitignore`, `.env.example`, 패키지 목록 작성
- Render/Vercel 배포 파일의 기본 구조 마련

### 검증

- 실제 키·건강 원본 파일이 추적 대상에 없는지 확인
- 요구사항의 필수 엔드포인트가 계획에 모두 포함되었는지 확인

### 종료 조건

새 세션이 문서만 읽고도 구현 범위와 보안 경계를 이해할 수 있다.

### 롤백

문서 및 빈 골격 파일만 제거하면 된다.

## Step 2 — 백엔드 기반, 인증, 저장소

### 컨텍스트

FastAPI 앱 팩토리, CORS, 설정, Firebase 초기화, 토큰 검증, Firestore 저장소 계층을 구현한다. 로컬 테스트는 인메모리 저장소로 격리한다.

### 작업

- Pydantic 설정과 환경 변수 파싱
- Firebase 서비스 계정 JSON 초기화
- Bearer 토큰에서 Firebase UID 검증
- Firestore/인메모리 저장소 인터페이스
- `/health` 및 오류 응답 규격

### 검증

- 인증 없음은 401
- 다른 UID의 문서는 조회·수정·삭제 불가
- 인메모리 모드에서 앱이 외부 서비스 없이 기동

### 종료 조건

인증과 사용자 격리가 라우터에서 재사용 가능한 의존성으로 제공된다.

### 롤백

라우터 등록을 제거하고 앱 골격 상태로 되돌린다.

## Step 3 — 데이터, 요약, 프로필

### 컨텍스트

과제의 `(date, value, memo)` 계약을 유지하면서 `activity`와 `weight` 레코드를 지원한다.

### 작업

- 데이터 CRUD 5개 엔드포인트
- 프로필 생성·조회·수정과 성인 검증
- 체중 체크인과 주간 알림 상태
- 기간·개수·평균·최대·최소·최근 추세 계산
- CSV 내보내기
- BMI 참고 지표와 안전 가이드
- 로컬 삼성 헬스 ZIP 미리보기·가져오기 도구
  - `activity.day_summary`만 읽기
  - Asia/Seoul 날짜로 정규화
  - `(uid, activity, date)` 중복 제거
  - 기본은 미리보기이며 명시적 `--apply`에서만 API 저장
  - ZIP 자체는 업로드하거나 복사하지 않음

### 검증

- 100개 이상 레코드 요약 테스트
- 실제 내보내기에서 정규화한 100개 이상 레코드를 API/UI에서 확인
- 활동과 체중이 서로의 평균을 오염시키지 않는지 확인
- BMI 경계 17, 30과 목표 체중 확인 테스트

### 종료 조건

Swagger에서 CRUD, summary, profile, CSV 계약이 확인된다.

### 롤백

각 라우터를 독립적으로 비활성화할 수 있다.

## Step 4 — OpenAI 이미지 추출, 채팅, 목표 추천

### 컨텍스트

Responses API의 이미지 입력과 JSON Schema Structured Outputs를 사용한다. 사용자 이미지와 응답은 OpenAI 측 저장을 비활성화한다.

### 작업

- JPEG/PNG/WebP 형식·크기 검증
- 걸음 수·활동 시간·활동 칼로리·거리 구조화 추출
- 사용자 확인 전 DB 미저장
- 데이터 요약을 시스템 지침에 주입하는 채팅
- 단일 대화 자동 저장·복원·삭제
- 하나의 논리 대화를 유지하되 메시지는 Firestore 하위 문서로 분리하고 페이지 단위로 조회
- 100보 단위 목표 추천과 사용자 수락 흐름
- 운동 범위 밖 의료 질문 안전 응답

### 검증

- 이미지가 아닌 파일 거부
- 구조화 결과 누락·불확실성 표시
- API 키 미설정 및 OpenAI 오류가 안전한 503으로 변환
- 채팅 후 대화가 자동 저장되는지 확인

### 종료 조건

스크린샷에서 추출한 값을 사용자가 검토할 수 있고, 채팅이 실제 요약을 반영한다.

### 롤백

AI 라우터만 비활성화해도 CRUD 앱이 정상 동작한다.

## Step 5 — 모바일 프론트엔드 앱 셸

### 컨텍스트

390px 모바일 화면을 우선으로 홈·기록·채팅·기록 탐색·설정 5개 화면을 구현한다.

### 작업

- Google 로그인과 온보딩 화면
- 둥근 카드, 코랄·네이비 디자인 토큰
- 하단 내비게이션과 반응형 중앙 앱 셸
- 라이트·다크 모드 및 시스템 테마
- loading/empty/error/partial/success/permission 상태

### 검증

- 390x844 및 1440x900에서 레이아웃 점검
- 키보드 포커스, 명시적 라벨, 44px 터치 영역 확인
- reduced-motion에서 불필요한 애니메이션 제거

### 종료 조건

API 없이도 모든 상태를 확인할 수 있는 안정적인 앱 셸이 완성된다.

### 롤백

정적 자산만 제거하면 백엔드와 독립적으로 되돌릴 수 있다.

## Step 6 — 프론트엔드 API 연결과 보너스

### 컨텍스트

Firebase ID 토큰을 모든 백엔드 요청에 전달하고 실제 데이터를 화면에 연결한다.

### 작업

- Vercel 환경 변수 기반 런타임 설정
- Vercel 서버리스 `/api/config`가 공개 가능한 API/Firebase 웹 설정만 반환
- 프로필·CRUD·이미지 추출·채팅 연결
- 목표 추천 수락과 체중 알림
- Chart.js 주간·월간 걸음 및 체중 그래프
- CSV 다운로드와 다크 모드

### 검증

- 토큰 만료 시 재발급 또는 재로그인 안내
- 중복 날짜 확인, 추출값 수정, 저장 성공 피드백
- 모바일 파일 선택과 이미지 미리보기

### 종료 조건

필수 사용자 흐름을 UI만으로 끝까지 수행할 수 있다.

### 롤백

API 어댑터를 데모 데이터 모드로 전환해 UI를 독립 실행한다.

## Step 7 — 테스트, 문서, 배포 검증

### 컨텍스트

구현 결과를 자동 테스트, 렌더링 검사, README 및 배포 체크리스트로 마감한다.

### 작업

- pytest 서비스·API 테스트
- 정적 JS 문법과 접근성 점검
- Render/Vercel 설정 및 콜드스타트 UX
- README, 환경 변수, Swagger, 스크린샷 체크리스트
- 계정·전체 데이터 삭제, AI 호출 제한, 개인정보 처리 고지
- 실제 키 없이 재현 가능한 데모 절차

### 검증

- 테스트 전체 통과
- 민감 파일과 비밀값이 Git 대상에 없는지 검색
- 모바일·데스크톱 렌더링 증거 기록

### 종료 조건

새 환경에서 README만으로 실행·배포할 수 있고 제출 요건을 추적할 수 있다.

### 롤백

배포 구성은 애플리케이션 코드와 분리해 제거 가능하게 유지한다.

## 계획 변경 규칙

- 필수 과제 조건에 영향을 주는 변경은 이 문서와 제품 요구사항을 함께 수정한다.
- 보너스 기능은 핵심 기능 검증을 방해하면 후순위로 이동한다.
- 실제 계정·키·외부 배포가 필요한 단계는 사용자 제공 또는 승인 없이는 완료로 표시하지 않는다.
- 새 데이터 유형을 추가할 때는 요약·CSV·프롬프트·UI 표시를 함께 갱신한다.
